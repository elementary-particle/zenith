# V18 旧输入冗余代码清理提示词

在项目 `/mnt/disk1/hubowen/zenith` 中，对当前 V18 重构后**已经不再被使用的旧 V18 输入/状态
编码冗余代码**做一次彻底清理：删除新增 V18 输入协议（当前局面快照 + Action Query 融合 +
Actor-only SFT）之后留下的死代码、死导出与过时文档/注释；**必须保留**当前 V18 需要的全部代码，
**必须保留** PPO/rollout/learner/worker/inference/eval/1v3/GRP/riichi_lab_bot 训练路基（即使它们
仍引用旧输入契约，也只标记为待迁移，不清理、不兼容、不测试）。

## 一、目标与范围

- **删除对象**：在当前 V18（`prepare_current_state_batch` + `encode_query_batch` +
  `StateTokenEmbedding` + `KyokuTransformerActorCritic` + `sft/` 全链路）下**零引用**的
  - 旧 54 行原子 Snapshot 编码/Rust 模块/导出/帮助函数及其测试；
  - 旧 per-player semantic-token 路径（仅被其自身测试引用）；
  - 模型侧死类/死常量/占位符/无用 import；
  - 相应过时注释与文档表述。
- **保留对象**（严禁删除/改动语义）：
  - 当前 V18 全部路径：`riichienv.prepare_current_state_batch`、`riichi.encode_query_batch`、
    `riichienv.prepare_encoding_facts`、`riichienv.analyze_encoding_yaku_batch`、
    `riichi_ppo_v1/model/current_state.py`、`dense_embedding.py`（StateTokenEmbedding 生产路径）、
    `architecture.py`、`semantic_validation.py`、`native_encoding.py`、`action_groups.py`、
    `validation.py`、`bridge.py`、`critic_features.py`、`sft/*`、`configs/v18_*`；
  - PPO 训练路基：`riichi_ppo_v1/training/{rollout_buffer,learner,worker,inference,metrics,trajectory}*`、
    `evaluation/*`、`riichi_lab_bot/*`、`training/grp/*`；其中对旧 history/snapshot 字段的引用
    保持原样（属待迁移），**不得**为了让某条 import 通过而重新引入已删除常量；
  - 状态机中仍被使用的能力：`manager.prepare_decisions`（SFT/bridge 取 legal mask，PPO 全量消费）、
    `decode_actions`、`query_encoding.rs`、`offense_analysis.rs`、`MjaiKyokuStateMachine/types.rs`；
  - Rust 侧 `encoding_facts.rs` 中被当前编码器使用的函数：
    `observation_facts`、`prepare_encoding_facts`/`CompactEncodingFacts`、
    `analyze_encoding_yaku_batch`/`EncodingYakuValues`、`decompose_melds`、`kernel_shape`、
    `tile_counts`、`count_dora_aka`、`open_meld_yakuhai_han`、`visible_meld_dora_aka_han`、
    `dora_type`、`physical_tiles`、`remove_by_type`；
  - 归档资产：`specs/008-*`（旧 V18 spec 参考）、`audit/reports/v16|v17`、`checkpoints/*`、
    `datasets/*`、`logs/v16|v17` 一律只读，不修改不删除；

    它们引用 `SNAPSHOT_YAKUHAI_HAN_OVERFLOW_BUCKET`（=6）与
    `SNAPSHOT_VISIBLE_MELD_DORA_AKA_OVERFLOW_BUCKET`（=8）；删除 atomic_snapshot 模块前，
    必须先把这两个溢出桶常量迁移到保留的单一常量位置（如 `riichienv-state-machine/src/lib.rs`
    或 `types.rs` 的常量区，Rust/Python 镜像 + 交叉一致性测试），禁止直接删除导致编译失败。

## 三、执行流程（每主题一个 commit，先证死再删）

1. 起点记录：`git log --oneline -5`、`git status --short`、扩展版本
   （`riichi.ENCODING_PROTOCOL_VERSION`/`ANALYSIS_VERSION`、`riichienv.REPLAY_SEMANTICS_VERSION`）。
2. 对每个候选对象执行**全仓 `rg` 引用检查**（覆盖 `.rs/.py/.pyi/.md`），把命中分为：
   - 活跃 V18/PPO 依赖 → **不删**；
   - 仅测试或仅自身 → 可删（先迁移/删除测试）；
   - 历史报告/归档文档 → 保留原貌。
3. 每个主题按「失败测试(如有)→删除→编译/测试→提交」执行；删除后立即跑：
   ```bash
   env LD_LIBRARY_PATH=/mnt/disk1/hubowen/miniconda3/envs/Mahjong-AI/lib \
     conda run --no-capture-output -n Mahjong-AI cargo test --manifest-path RiichiEnv/Cargo.toml --workspace
   conda run --no-capture-output -n Mahjong-AI python -m pytest -q \
     riichi_ppo_v1/tests/unit riichi_ppo_v1/tests/protocol riichi_ppo_v1/tests/integration
   conda run --no-capture-output -n Mahjong-AI python -m pytest -q RiichiEnv/tests
   conda run --no-capture-output -n Mahjong-AI python -m riichi_ppo_v1.tools.validate --parameter-contract
   conda run -n Mahjong-AI python audit/reports/v18/scripts/v18_audit_oracle.py
   conda run -n Mahjong-AI python audit/reports/v18/scripts/v18_model_structure_audit.py
   ```
4. 已知**不得修复**的失败项（保持原样并在报告中列出）：
   - `unit/test_artifact_conventions.py::test_historical_audit_and_logs_are_removed_but_checkpoints_remain`
     （本机 checkpoints 缺 train_riichi_v13，环境资产项）；
   - `unit/test_rollout_buffer.py::test_learner_accepts_only_rollout_buffer`
     （PPO learner 仍传 `history_factors`，待迁移）；
   - `riichi_lab_bot/tests` collection 失败（import 已删常量，待迁移）。
