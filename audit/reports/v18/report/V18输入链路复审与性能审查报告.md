## §8 真实数据训练首跑发现的校验器缺陷（V18-VAL-1，P2，已修复）

**现象**：正式 60% 数据集生成成功（validation 1,439,440 决策 / `actor_mean=109.0` / `actor_max=165` ≤256）后，
SFT 训练首批 batch 在 `collate_samples → assert_actor_input_semantics` 抛
`AssertionError: SELF_HAND requires at least one nonzero kind`。

**根因（数据正确，校验器 off-by-one）**：合法「四副露 + 对子」的和牌决策，闭手**只有一种牌**——
例如 `2024021011gm-00a9-0000-07d2a4be` kyoku0 seat3 step19（3 碰 + 1 吃 + 对子 `[44,44]`，tsumo，
action=239），Rust 编码器正确输出 **恰好 1 行 SELF_HAND**。但
`semantic_validation._assert_actor_canonical_order` 在校验 `SEP_SELF_HAND(101) + SELF_HAND(3)` 后
执行 `cursor += 2`，把**第一行 SELF_HAND 跳过**——只要 SELF_HAND 恰好 1 行就被误判为“空手”。
此缺陷在 12 局审计 fixture 中未暴露（fixture 手牌都有多个牌种）。

**影响**：SFT 训练无法开始；**编码数据集本身无需重生成**（该样本的输入是正确的）。

**修复**：`semantic_validation.py` 将 `cursor += 2` 改为 `cursor += 1`（SEP 校验已确认下一 kind 为
SELF_HAND，光标应停在其第一行，由 while 从它开始消费并校验升序/域）。新增回归测试
`test_v18_replay_bridge.py::test_single_self_hand_row_all_meld_pair_accepted`。

**验证**：真实异常 kyoku 的 74 个决策（含恰好 1 行 SELF_HAND 的 tsumo 样本）全部通过
`assert_actor_input_semantics`；pytest 全绿。**训练可直接用已有数据重跑**
`bash audit/reports/v18/scripts/run_v18_precompute_and_sft.sh --skip-precompute`。

旧基准 rank1 实际跑在 **T400 4GB** 上。用正确 2×L20 重测：**旧版 100 步 = 5.29s（≈53ms/步）**。

**已实施优化**（全部保持输出逐位一致 / 语义不变）：
1. `dense_embedding.StateTokenEmbedding` 向量化（分隔符 `tolist()` 28k 元素 CPU 往返 →
   纯向量化 mask；逐类 `nonzero` → 一次 stable `argsort` 分段）：`token_embedding` 36→**7ms**；
2. `architecture._assert_structure` 整批向量化（逐行 `tolist()` → segment 查表 + boolean mask）：
   ~32ms → **~1ms**；fwd 50→**19ms**；
3. `torch.compile` 仅单卡可用（+30%），**DDP 下退化 8s/步**（IndexPutBackward0 图断裂），
   配置默认关闭。

（data 3 + fwd 19 + bwd 42 + opt 1）——差距从修复前 ~2.4× 收敛到 ~1.2×，属新输入协议的固有成本。
数据集无需重生成；重启训练后生效。
