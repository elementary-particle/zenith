## 0. 2026-08-17 V16-small 修订

版本命名保持 V16,输入/输出协议不变(编码数据集可复用),仅下调隐藏层容量:

| 参数 | 原 V16 大模型 | V16-small |
| --- | ---: | ---: |
| `d_model` | 256 | **192** |
| Q heads | 16 | **12** |
| KV heads | 4 | **3** |
| head dim | 16 | **16** |
| FFN | 1088 | **576** |
| Shared Transformer | 4 layers | **3 layers** |
| Actor-only Transformer | 1 layer | **1 layer** |
| Critic-only Transformer | 2 layers | **2 layers** |
| 总参数量(含 Top-3 Q scorer) | ~7.6M | **约 3.0M** |

实测总参数 3,081,603、Actor 推理 2,043,073。GRP 模型与奖励契约不修改。
SFT 数据从 40% 扩到 60%:复用 `..._encoded_40pct_v16`,仅追加 remainder=2 的
20% 新编码,最终为 `datasets/tenhou_sft_2024_2025_encoded_60pct_v16`。

## 1. V16 目标

V16 主要解决以下问题：

1. 将当前约 2.86M 参数的 Actor-Critic 扩展到约 **7～8M**，提升模型容量。
2. 重构 Actor 输入，删除大量重复或人为设计的 Derived Features。
3. 保留每个合法动作对应的 **Offense Query + Defense Query**，并改为统一固定 Schema。
4. Offense / Defense Query 对称参与 Actor 输出，不再对 Offense 分支做零初始化。
5. Critic 继续使用 privileged information，并采用 Top-3 Candidate Q-boosting。
6. PPO reward 改为 **70% GRP + 30% 小局分差**。
7. 新增一个轻量 GRP 模型，离线训练后在 PPO 阶段冻结。

# 2. 主网络结构

推荐配置：

| 参数 | V16 |
|---|---:|
| `d_model` | **256** |
| Q heads | **16** |
| KV heads | **4** |
| head dim | **16** |
| FFN | **1088** |
| Shared Transformer | **4 layers** |
| Actor-only Transformer | **1 layer** |
| Critic-only Transformer | **2 layers** |
| 总参数量 | **约 7.5～7.8M** |
| Actor 推理参数 | **约 5.3M** |

网络仍采用当前的 GQA + gated FFN 结构。

Actor 路径总深度：

```text
4 Shared + 1 Actor = 5 layers
```

Critic 路径：

```text
4 Shared + 2 Critic = 6 layers
```

与当前版本相比，扩容主要来自：

```text
d_model: 192 → 256
Attention Heads: 8 → 16
KV Heads: 2 → 4
FFN: 576 → 1088
Shared Layer: 3 → 4
```

不继续把 hidden size 拉到 288/320，避免参数量过度依赖网络宽度。

# 3. Actor 输入结构

V16 Actor 输入统一划分为：

```text
Objective Facts
      +
Compact Snapshot
      +
Offense / Defense Queries
```

## 3.1 Objective Facts

保留目前的原始事实输入，包括：

- 自己当前手牌；
- 历史事件；
- 摸牌；
- 打牌；
- chi / pon / kan；
- reach / reach accepted；
- 和牌 / 流局等事件；
- 其他当前已经存在的基础客观事件。

历史事件继续承担完整公共信息记录职责。

---

# 4. Snapshot

删除当前所有 Derived Features。

同时删除 Snapshot 中对：

- 三家完整牌河；
- 三家完整副露序列；

的重复表示。

这些信息已经存在 Historical Events 中。

Snapshot 只负责提供模型不应该反复从长历史中重新计算的当前状态。

包括：

### 基础场况

- 场风；
- 局数；
- 庄家；
- 本场；
- 立直棒；
- 剩余牌数；
- 宝牌指示；
- 四家当前点数；
- 当前顺位。

### Score Pressure

增加自己的排名压力信息，例如：

```text
self_score - player_1_score
self_score - player_2_score
self_score - player_3_score
```

或者等价的三个相对分差。

目标是让模型无需从四个绝对点数自行学习所有排名关系。

### Opponent Summary

三个对手分别增加固定 7 个 Summary Token：

```text
1. 是否立直
2. 立直巡目
3. 副露数
4. 是否门清
5. 舍牌数
6. 手切次数
7. 摸切次数
```

共：

```text
3 × 7 = 21 Summary Tokens
```

详细牌河和副露仍然从 Historical Events 中读取。

# 5. Unified Action Query Schema

每一个合法动作固定生成：

```text
Action a
 ├── Offense Query(a)
 └── Defense Query(a)
```

两个 Query 使用完全相同的数据结构：

```text
ActionQuery
├── query_type
├── action_id
├── action_type
├── primary_tile
├── source_seat
│
├── answer_0
├── answer_1
├── ...
└── answer_9
```

即：

> **一个 Query 固定包含 10 个 Question Answer Slot。**

`query_type` 为：

```text
OFFENSE
DEFENSE
```

不同 Query Type 下，`answer_0 ~ answer_9` 对应不同问题。

每个 Slot 使用独立的 categorical/bucket embedding。

推荐最终 Query Embedding：

\[
E_q =
E_{action}
+
E_{queryType}
+
\sum_{i=0}^{9}E_{type,i}(answer_i)
\]

再经过 LayerNorm / Projection 转换到：

\[
d_{model}=256
\]

这样 Query 本身仍然只是 **一个 Transformer Token**，不会因为增加问题而增加 sequence length。

# 6. Offense Query

Offense Query 回答：

> **“如果执行这个 Action，执行之后我的手牌进攻状态是什么？”**

推荐固定 10 个问题。

| Slot | Question |
|---|---|
| O0 | 执行动作后多少向听？ |
| O1 | 动作后的有效牌种类数是多少？ |
| O2 | 动作后的有效牌剩余总枚数是多少？ |
| O3 | 如果听牌，合法等待牌种类数是多少？ |
| O4 | 当前等待是否有役？ |
| O5 | 当前等待的基础番数范围是多少？ |
| O6 | 动作后是否振听？ |
| O7 | 动作后是否仍然门清？ |
| O8 | 动作后是否满足立直条件？ |
| O9 | 动作后手中保留的宝牌/赤牌数量是多少？ |

---

## O0：动作后向听数

编码：

```text
AGARI
0
1
2
3
4
5+
```

这是最核心的进攻信息。

---

## O1：有效牌种类数

即：

> 有多少种牌可以让向听数下降。

例如：

```text
3 kinds
7 kinds
12 kinds
```

可以直接 bucket 化。

---

## O2：有效牌剩余枚数

区别于 O1。

例如：

```text
有效牌：
3m × 4
6m × 2
9p × 3

O1 = 3
O2 = 9
```

状态机维护 visible tiles 后可以非常便宜地计算。

Actor 不需要接收完整 34 维剩余牌统计。

---

## O3：合法等待牌种类数

只有 `shanten = 0` 时有意义。

否则：

```text
N/A
```

例如：

```text
3m / 6m
→ 2 waits
```

---

## O4：是否有役

不建议简单编码 Boolean。

建议：

```text
N/A
NO_YAKU
PARTIAL_YAKU
ALL_YAKU
```

其中：

- `NO_YAKU`：所有等待均无役；
- `PARTIAL_YAKU`：部分等待可以合法和牌；
- `ALL_YAKU`：所有等待均有至少一个役。

这样能表达类似：

> 同样听牌，但是部分等待会无役。

---

## O5：基础番数

仅针对当前听牌状态。

建议 bucket：

```text
N/A
1
2
3
4
5+
```

只统计可以确定的基础番数。

不加入：

- 里宝；
- 一发；
- 海底等偶然条件。

目的不是估计 EV，而是告诉模型一个客观的手牌价值事实。

---

## O6：振听状态

编码：

```text
N/A
NO_FURITEN
PERMANENT_FURITEN
TEMPORARY_FURITEN
```

听牌质量不仅取决于 wait 数量，也取决于是否能够荣和。

---

## O7：动作后是否门清

```text
YES
NO
```

对于吃碰杠等动作尤其重要。

---

## O8：动作后是否可以立直

```text
YES
NO
N/A
```

这是非常高信息密度的客观特征。

---

## O9：动作后保留的宝牌/赤牌数

建议直接编码：

```text
0
1
2
3
4
5+
```

这里统计当前手牌中实际持有的：

```text
dora + aka
```

不计算预期打点。

---

# 7. Defense Query

Defense Query 回答：

> **“执行这个 Action 后，这个动作面对三个对手的防守性质是什么？”**

同样固定 10 个问题。

| Slot | Question |
|---|---|
| D0 | 候选打牌是否为对手 1 的现物？ |
| D1 | 候选打牌是否为对手 2 的现物？ |
| D2 | 候选打牌是否为对手 3 的现物？ |
| D3 | 候选打牌是否对对手 1 构成筋关系？ |
| D4 | 候选打牌是否对对手 2 构成筋关系？ |
| D5 | 候选打牌是否对对手 3 构成筋关系？ |
| D6 | 动作后手中还有多少张对手 1 的现物？ |
| D7 | 动作后手中还有多少张对手 2 的现物？ |
| D8 | 动作后手中还有多少张对手 3 的现物？ |
| D9 | 当前候选牌已经公开出现多少张？ |

---

## D0～D2：现物

三个 opponent-relative slot：

```text
GENBUTSU
NOT_GENBUTSU
N/A
```

对于没有实际打牌的 action，例如某些 call action：

```text
N/A
```

---

## D3～D5：筋

三个 opponent-relative slot：

```text
SUJI
NOT_SUJI
N/A
```

不直接输入：

```text
danger = 0.23
```

这种人为风险评分。

模型只获取：

> “它是否满足这个客观关系。”

风险大小由网络自己学习。

---

## D6～D8：动作后的安全牌库存

这是建议增加的一个重要特征。

例如执行某个碰牌之后：

```text
对家已立直

Action A 后：
手里还剩 3 张现物

Action B 后：
手里只剩 0 张现物
```

虽然两个动作现在可能没有直接放铳风险，但：

> Action B 明显降低了之后的防守空间。

因此分别记录：

```text
safe tiles vs opponent 1
safe tiles vs opponent 2
safe tiles vs opponent 3
```

建议 bucket：

```text
0
1
2
3
4+
```

这对：

- 吃；
- 碰；
- 杠；
- 不同打牌选择；

都有意义。

---

## D9：候选牌公开出现数量

状态机维护：

```text
visible_count[34]
```

但不把整套 34 维信息输入 Actor。

对于当前 action 只查询：

```text
visible_count[action_tile]
```

编码：

```text
0
1
2
3
4
N/A
```

这样基本没有输入长度开销。

# 8. Query 的核心原则

Offense / Defense Query 可以包含计算出来的分析结果，但需要满足：

> **它必须是能够从当前真实游戏状态确定计算出的客观答案。**

允许：

```text
向听
有效牌
等待
有无役
振听
现物
筋
公开牌数量
安全牌库存
```

暂时不加入：

```text
预计和率
预计放铳率
预计 EV
预计最终得点
人工危险度
手牌综合评分
```

这些已经属于另一个预测模型的结论。

V16 应该让 Transformer 自己学习：

\[
Objective\ Facts
+
Action\ Facts
\rightarrow
Action\ Utility
\]

# 9. Actor Policy Head

V16 不再使用：

```text
Defense hidden
+
zero-init Offense residual
```

而是：

```text
Offense(a) ───────┐
                  │
                  ├── CONCAT
                  │     ↓
Defense(a) ───────┘  Linear 512→256
                        ↓
                       SiLU
                        ↓
                    Policy MLP
                        ↓
                     Logit(a)
```

形式上：

\[
h_a=
f([h^{offense}_a;h^{defense}_a])
\]

\[
logit(a)=PolicyHead(h_a)
\]

Offense / Defense：

- 地位完全对等；
- 普通初始化；
- 从头参加 SFT。

因此 **V16 必须重新训练 SFT**。

# 10. Critic 输入

Critic 不增加 Action Query Token。

输入保持：

```text
Encoded Objective Facts
+
Snapshot
+
Score Pressure
+
Opponent Summary
+
Opponent Hidden Hand × 3
+
Next Wall Tiles × 5
+
Value Query
```

即：

```text
Public Information
        +
Privileged Information
        ↓
4 Shared Transformer
        ↓
2 Critic Transformer
        ↓
Value Query Hidden
```

# 11. Top-3 Q-boosting

不再输出：

```text
Q(s,a0)
Q(s,a1)
...
Q(s,a240)
```

Actor 先产生所有合法动作概率：

\[
\pi(a|s)
\]

选择：

```text
Top-1
Top-2
Top-3
```

然后 Critic Q scorer 只评估三个 candidate。

输入：

\[
[z_{critic};h_a]
\]

其中 Actor action representation：

\[
h_a=\operatorname{detach}(h_a)
\]

避免 Q loss 通过 action representation 直接更新 Actor。

Q scorer：

```text
Critic Value Hidden 256
          +
Action Hidden 256
          ↓
        512
          ↓
     Linear 512→256
          ↓
         SiLU
          ↓
      Linear 256→1
```

得到：

```text
Q1
Q2
Q3
```

### Critic 训练

如果实际 rollout behavior action 不在 Top-3：

```text
training candidates =
Top-3 ∪ Behavior Action
```

最多计算 4 个 Q。

### Q-boost

真正对 Actor 进行 boosting 时：

```text
boost candidates = Top-3
```

这利用了当前 SFT：

> Recall@3 已经接近 98%

这一特点，大幅减少无意义 Action-Q 学习。

---

# 12. GRP Reward

V16 PPO：

\[
R =
0.7R_{GRP}
+
0.3R_{Score}
\]

GRP 的排名 utility 推荐：

\[
\boxed{
[12,\ 4,\ -6,\ -10]
}
\]

即：

| 最终排名 | Utility |
|---|---:|
| 一位 | **+12** |
| 二位 | **+4** |
| 三位 | **-6** |
| 四位 | **-10** |

相比原来的类似：

```text
[10, 4, -4, -10]
```

V16 明确：

- 加大争一能力；
- 提高掉入三位的代价；
- 保持四位仍然是最差结果。

同时：

\[
12+4-6-10=0
\]

整体 utility 保持中心基本对称。

---

# 13. GRP 输出

GRP 不直接预测 reward。

对一个目标玩家输出：

\[
P(rank=1),
P(rank=2),
P(rank=3),
P(rank=4)
\]

然后：

\[
V_{GRP}
=
12P_1
+
4P_2
-
6P_3
-
10P_4
\]

小局 GRP reward：

\[
R^{GRP}_k
=
V_{k+1}-V_k
\]

最后一局结束后使用真实最终排名：

\[
V_{terminal}
=
U(rank_{real})
\]

而不是继续使用 GRP 预测。

# 14. GRP 模型

GRP 必须非常轻。

推荐：

```text
Input Features
      ↓
Linear → 64
      ↓
2-layer GRU
hidden = 64
      ↓
Linear 64→32
      ↓
SiLU
      ↓
Linear 32→4
      ↓
Rank Softmax
```

总参数约：

```text
50K～70K
```

相对于 7M+ Actor-Critic 基本可以忽略。

并且 GRP 只需要在：

> **每个小局边界**

执行一次，而不是每个 action 执行一次，因此不会成为 rollout 性能瓶颈。

---

# 15. GRP 输入

每个玩家按照：

```text
SELF
RIGHT
ACROSS
LEFT
```

旋转到统一视角。

一条 GRP sequence 对应完整一个半庄。

每个小局 boundary 输入：

### 当前比赛状态

```text
4 家当前点数
SELF 与其他三家的分差
SELF 当前排名
场风 / 局数
庄家相对位置
honba
riichi sticks
```

### 上一小局结果

```text
4 家 score delta
结果类型
winner seat
deal-in seat
流局 tenpai mask
庄家是否连庄
```

第一小局使用：

```text
START
```

作为 previous-result。

推荐对类别字段采用小型 embedding，例如：

```text
round          → Embedding
dealer         → Embedding
rank           → Embedding
result_type    → Embedding
winner         → Embedding
deal-in        → Embedding
tenpai_mask    → Embedding
```

点数和分差使用连续数值归一化。

最终拼接向量大约只有：

```text
40～60 dimensions
```

然后投影到 64。

暂时**不加入完整手牌、牌河、牌山等高维信息**。

# 16. GRP 训练

直接从当前使用的：

```text
Tenhou 2024 + 2025
40% dataset
```

构造训练集。

每一个完整半庄可以旋转产生：

```text
4 个 player-relative samples
```

例如一个半庄：

```text
Player A → sequence → final rank 2
Player B → sequence → final rank 4
Player C → sequence → final rank 1
Player D → sequence → final rank 3
```

每一个 prefix 都监督最终排名：

\[
L_{GRP}
=
\frac{1}{K}
\sum_{k=1}^{K}
CE(P_\phi(rank|s_{0:k}),rank_{final})
\]

训练完成后：

> **GRP 完全冻结。**

PPO 不更新 GRP。

# 17. Reward 归一化

由于：

```text
GRP delta
```

和：

```text
score delta / 1000
```

天然方差不同，因此不能直接按数值做 70/30。

先在训练数据上离线统计：

\[
\sigma_{GRP}
\]

和：

\[
\sigma_{Score}
\]

然后固定：

\[
\hat R_{GRP}
=
clip(R_{GRP}/\sigma_{GRP},-5,5)
\]

\[
R_{Score}
=
clip(\Delta score/1000,-12,12)
\]

\[
\hat R_{Score}
=
clip(R_{Score}/\sigma_{Score},-5,5)
\]

最终：

\[
\boxed{
R =
0.7\hat R_{GRP}
+
0.3\hat R_{Score}
}
\]

训练过程中不动态修改这两个标准差。

# 18. V16 训练流程

完整训练流程：

```text
Tenhou 2024/2025
        │
        ├───────────────┐
        │               │
        ▼               ▼
      SFT Dataset      GRP Dataset
        │               │
        ▼               ▼
   V16 Actor SFT     Train GRP
        │               │
        │          Freeze GRP
        │               │
        └───────┬───────┘
                ▼
             PPO
                │
        GRP + Score Reward
                │
       Privileged Critic
                │
         Top-3 Q-boost
```

由于：

- hidden size 改变；
- Transformer 深度改变；
- Input Schema 改变；
- Derived Features 删除；
- Summary Token 新增；
- Offense / Defense Query Schema 改变；
- Query Fusion 改变；

因此：

> **V16 从头重新训练 SFT，不继承旧 SFT 参数。**
